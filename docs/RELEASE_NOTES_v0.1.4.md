# PulseClip v0.1.4 — 녹화 안정성과 로컬 편집

작성일: 2026-09-10. 로컬 검증 빌드이며 GitHub 공개 배포는 수행하지 않았다.

## 추가한 기능

- 플레이어에서 시작·종료 시간을 선택하고 새 MP4로 구간 저장. 원본 보존, 진행률, 취소, 선택 구간 미리보기.
- 클립 이름 변경과 0.5×/1×/1.5×/2× 재생.
- 최신·오래된·큰 용량·긴 영상 정렬, 편집/복구 필터, 검색 결과 수와 용량, 24개씩 표시.
- 성능 우선·균형·선명하게 품질 프리셋과 시간당 녹화/리플레이 메모리 예상 용량.
- 저장 한도 자동 정리 켜기/끄기, 커서 녹화 설정, 변경사항 되돌리기.
- 사용자 요청으로 GitHub 공식 안정 릴리스 확인 및 공식 다운로드 페이지 열기.

## 수정한 문제

1. 캡처 소스와 변환 단계의 이중 FPS 보정으로 GOP 타임스탬프가 역전되는 오류를 수정했다. 합성 영상으로 재현하고 수정 후 녹화와 동시 리플레이를 검증했다.
2. 같은 초에 시작한 저장 작업과 기존 `.part` 파일 간 이름 충돌을 배타적 생성으로 방지했다.
3. 설정/폴더/메타데이터 동시 변경을 직렬화해 갱신 유실을 막았다. 파일 저장 중 폴더 변경을 차단한다.
4. 부분 디스크 쓰기를 반복 처리하고 중복 종료 요청은 동일 작업을 기다린다.
5. 저장 완료 직후 한도 정리가 방금 저장한 큰 클립을 삭제하지 않도록 보호했다. 편집 중인 원본도 자동/수동 삭제에서 보호한다.
6. 느린 디스크에서 패킷 쓰기 큐가 64 MiB를 넘으면 녹화를 중단하고 오류를 표시한다. 큰 muxer 청크는 8 MiB 이하 IPC로 나눈다.
7. 알림 실패를 영상 저장 실패로 보고하지 않는다. 종료 시 진행 중 시작/리플레이/편집 정리를 기다린다.
8. 미디어 URL을 앱과 동일 출처로 제공하며 GET/HEAD와 실제 206/416 byte-range 스트리밍을 구현했다. 파일 전체를 읽지 않고 필요한 범위만 전달한다.
9. 소스 조회 실패가 보관함과 설정의 앱 시작까지 막지 않도록 분리했다.
10. 폴더 변경 시 미저장 화질 설정이 사라지는 문제와 반복 즐겨찾기로 카운트가 틀어지는 문제를 수정했다.
11. 중복·잘못된 단축키를 저장 전 검증하고 등록 예외가 앱 시작을 중단하지 않도록 처리했다.
12. 화면 밖 영상의 로딩과 최초 표시 클립 수를 제한했다. 범위 요청마다 보관함 전체를 재검색하던 경로는 저장 폴더별 ID 인덱스로 개선했다.
13. 미디어 라이브러리의 로컬 Blob 작업자만 CSP에서 허용해 백그라운드 타이머/미디어 작업자 차단을 해소했다. 일반 스크립트와 네트워크 출처 제한은 유지한다.
14. 지원 검사와 실제 인코더 선택 조건을 일치시켰다. GPU 인코딩을 사용할 수 없는 환경에서 하드웨어 인코더를 요구해 복구를 반복하던 문제를 소프트웨어 인코딩 허용으로 해결했다.
15. 장치 복구 중에는 녹화 시작·리플레이 저장을 막고 복구 상태와 취소 방법을 안내한다. 진단 화면의 H.264 해상도와 인코더 설명도 실제 검사 조건에 맞췄다.
16. 영상과 오디오의 첫 인코딩 패킷을 받은 뒤에만 리플레이 준비 완료를 표시한다. 초기화 중 오류는 시작 실패로 처리하고, 실패한 버퍼를 정리해 재시작·복구에 이전 데이터가 섞이지 않도록 했다.

## UI/UX와 구조

- 홈에 현재 작업과 다음 동작을 표시하고 선택된 소스의 대기 안내를 바로잡았다.
- 빈 보관함에서 홈으로 이동하는 동작과 사용자 지정 단축키 안내를 추가했다.
- 설정의 본문 가독성, 작은 창의 제어 배치, 편집 제어와 알림 겹침을 개선했다.
- 중첩 대화상자의 배경 포커스를 차단하고 영상 제어도 키보드 이동에 포함한다.
- 기존 통합 `Modals.tsx`를 소스 선택/온보딩/확인/플레이어로 나누고 공통 포커스 훅을 추출했다.
- 녹화 writer와 IPC sink, 검색·정렬, 편집 상태를 별도 모듈로 분리했다. CSS도 화면별 파일로 분리했다.
- 미사용 `build/icon.svg`, `landing/public/assets/pulseclip-app-home.jpg`를 제거했다. 문서가 참조하는 디자인/브랜드 산출물과 기존 사용자 캡처는 보존했다.
- TypeScript 미사용 지역 변수/매개변수 검사를 상시 활성화했다. 편집 진입점과 라이브러리 번들을 분리했다.
- 메인 프로세스 빌드 전에 이전 출력만 정리해 삭제된 소스와 오래된 테스트 JS가 설치 파일에 섞이지 않도록 했다.

## 검증과 범위

- 타입 검사, 미사용 코드 검사, 65개 단위 테스트, 데스크톱 프로덕션 빌드.
- 실제 Electron: 격리 저장소와 합성 화면·오디오로 녹화 → 동시 리플레이 → 이름 변경 → 1.5초 구간 편집 → 원본 보존 → MP4 재생 → 206 범위 요청.
- 1440×900/1080×700 레이아웃, 편집 취소, 미저장 설정 보호, 단축키 오류 처리.
- 랜딩 페이지 빌드와 8개 호스팅 테스트, 운영 의존성 보안 감사.
- Windows x64 NSIS 패키징과 Electron 퓨즈 검증.

실제 게임의 전체 화면·안티치트·여러 GPU·실제 시스템/마이크 장치·절전·장시간 부하·Arm64 환경은 이번 합성 미디어 검증으로 보장하지 않는다. 게임 이벤트 자동 하이라이트, 자동 게임 감지, 다중 오디오 트랙, 서명 기반 자동 설치 업데이트는 구현 범위에 포함되지 않는다. 구간 편집은 시작 위치에 따라 재인코딩되므로 무손실/무재인코딩을 보장하지 않는다.

기능 비교 근거: [DOR 공식 기능](https://clip.dor.gg/en). 미디어 구현은 설치된 MediaBunny 1.55.4 소스/타입과 [공식 미디어 읽기 가이드](https://mediabunny.dev/guide/reading-media-files)를 확인했다.
