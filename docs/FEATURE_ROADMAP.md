# PulseClip 기능 고도화 검토

검토 기준: 사용자 가치, 녹화 실패 위험, 현재 아키텍처와의 결합도, 구현·QA 비용, 로컬 우선 원칙.

문서 기준: PulseClip `v0.1.3`·2026년 8월 31일. 상태는 저장소의 구현과 공개 패키징 구성을 기준으로 한다.

## 현재 기준선

PulseClip은 화면/창 선택, 단일 인코딩 파이프라인, 15~180초 즉시 리플레이, 장시간 fMP4 기록, 시스템 오디오·마이크 믹스, 전역 단축키, 트레이, 로컬 클립 보관함, 즐겨찾기, 저장공간 자동 정리와 중단 파일 복구를 제공한다.

`v0.1.3`에서 다음 P0 신뢰성 기준선도 구현됐다.

- 코덱·오디오·저장 폴더·여유 공간·전역 단축키를 검사하고 개인정보를 제외한 JSON 보고서를 내보내는 진단 센터
- 녹화 시작 전 예상 용량 검사, 2 GiB 예약 공간 유지, 녹화 중 임계치 도달 시 파일을 정상 종료하는 디스크 안전 가드
- 캡처 소스·시스템 오디오·마이크 연결이 끊겼을 때 세 차례 재탐색하고, 필요하면 기본 마이크로 폴백한 뒤 일반 녹화를 새 파일로 이어가는 장치 복구

현재 구조에서 확인된 주요 공백은 다음과 같다.

- 진단 센터는 인코딩 가능 코덱을 확인하지만 실제 선택된 GPU·인코더, 드롭 프레임, 인코딩 지연과 쓰기 처리량은 아직 보여주지 않는다.
- 디스크 안전 가드와 장치 복구는 구현됐지만 Intel·NVIDIA·AMD, 다중 모니터, 절전 복귀와 장시간 녹화 조합의 실기기 회귀 매트릭스가 충분하지 않다.
- 장치 복구 후 일반 녹화는 데이터 보존을 위해 새 파일로 이어지며, 하나의 파일로 무중단 연결하지 않는다.
- Authenticode 코드 서명과 신뢰된 HTTPS 자동 업데이트 전달 체계가 없다.
- 게임 자동 감지, 게임별 설정 프로필, 클립 편집과 별도 오디오 트랙이 없다.

## 권장 개발 순서

### 1단계 — 녹화 신뢰성 기준선

진단 센터, 디스크 안전 가드, 소스·오디오 장치 복구의 제품 구현은 `v0.1.3`에서 완료했다. 다음 작업은 기능을 다시 만드는 것이 아니라 실제 GPU·오디오·모니터·절전 조합에서 회귀 범위를 넓히고, 실제 인코더와 드롭 프레임·지연·쓰기 처리량을 진단 센터에 연결하는 것이다.

### 2단계 — 신뢰된 배포

조직 명의 Authenticode 인증서로 실행 파일과 설치 프로그램을 일관되게 서명하고, 서명 검증을 통과한 산출물만 HTTPS 업데이트 피드에 게시한다. 단계적 배포, 실패 시 롤백, 업데이트 채널 분리를 함께 제공한다.

완료 기준:

- 설치 프로그램과 앱 실행 파일의 게시자 ID가 모든 지원 아키텍처에서 일치한다.
- 업데이트 전후 서명과 SHA-256을 검증하고 실패 시 기존 버전을 유지한다.
- 깨끗한 Windows 10 22H2·Windows 11 환경에서 설치, 업데이트, 롤백, 제거를 검증한다.

### 3단계 — 무설정 게임 경험

게임 자동 감지와 프로필을 추가한다. 처음에는 지원 목록을 좁게 유지하고 사용자가 매칭을 수정할 수 있게 한다. 프로세스 주입이나 안티치트 우회는 사용하지 않는다.

### 4단계 — 클립 완성도

비파괴 트림과 마커를 먼저 제공하고, 자막·효과보다 빠른 무재인코딩 내보내기를 우선한다. 이후 다중 오디오 트랙과 공유 프리셋을 연결한다.

### 5단계 — 차별화

게임별 공식 이벤트 소스가 안정적인 경우에만 자동 하이라이트를 플러그인 방식으로 추가한다. HDR·AV1은 별도 호환성 트랙으로 분리한다.

## 의도적으로 후순위로 둘 항목

- 커뮤니티 피드, 계정, 클라우드 업로드: PulseClip의 로컬 우선·무계정 가치와 운영 비용에 충돌한다.
- 생성형 AI 편집: 기본 트림·오디오·내보내기 신뢰성이 확보되기 전에는 비용 대비 핵심 과업 개선이 작다.
- DLL 주입 기반 게임 후킹: 안티치트, 보안, 유지보수 위험이 높다.
- 라이브 스트리밍: 녹화·즉시 리플레이 제품 범위를 크게 확장하므로 별도 제품 결정이 필요하다.
