# PulseClip 기능 고도화 검토

검토 기준: 사용자 가치, 녹화 실패 위험, 현재 아키텍처와의 결합도, 구현·QA 비용, 로컬 우선 원칙.

## 현재 기준선

PulseClip은 이미 화면/창 선택, 단일 인코딩 파이프라인, 15~180초 즉시 리플레이, 장시간 fMP4 기록, 시스템 오디오·마이크 믹스, 전역 단축키, 트레이, 로컬 클립 보관함, 즐겨찾기, 저장공간 자동 정리와 중단 파일 복구를 제공한다.

현재 구조에서 확인된 주요 공백은 다음과 같다.

- 캡처 소스·오디오 장치·GPU 장치 손실 후 자동 복구가 없다.
- 저장공간 정리는 클립 완료 후 실행되므로 장시간 녹화 중 디스크 고갈을 사전에 막지 못한다.
- 하드웨어 인코딩을 우선 요청하지만 실제 선택된 GPU/인코더, 드롭 프레임, 인코딩 지연을 사용자에게 보여주지 않는다.
- 게임 자동 감지, 게임별 설정 프로필, 클립 편집, 별도 오디오 트랙, 업데이트 전달 체계가 없다.

## 권장 개발 순서

### 1단계 — 녹화 신뢰성

진단 센터, 디스크 안전 가드, 소스·오디오 장치 복구를 먼저 구현한다. 이 세 항목은 편집이나 자동 하이라이트보다 신규 사용자의 첫 녹화 성공률에 직접 영향을 준다.

완료 기준:

- 녹화 시작 전 쓰기 가능한 안전 여유 공간과 인코더 지원 여부를 확인한다.
- 남은 공간이 설정 임계치에 도달하면 파일을 정상 종료하고 복구 가능한 메타데이터를 남긴다.
- 창 크기 변경, 모니터 재연결, 절전 복귀, 마이크 분리 상황을 사용자 데이터 손실 없이 처리한다.
- 진단 보고서에는 개인정보와 전체 파일 경로를 제외하고 앱 버전, OS, 코덱, 장치 상태, 최근 오류 ID만 포함한다.

### 2단계 — 무설정 게임 경험

게임 자동 감지와 프로필을 추가한다. 처음에는 지원 목록을 좁게 유지하고 사용자가 매칭을 수정할 수 있게 한다. 프로세스 주입이나 안티치트 우회는 사용하지 않는다.

### 3단계 — 클립 완성도

비파괴 트림과 마커를 먼저 제공하고, 자막·효과보다 빠른 무재인코딩 내보내기를 우선한다. 이후 다중 오디오 트랙과 공유 프리셋을 연결한다.

### 4단계 — 차별화

게임별 공식 이벤트 소스가 안정적인 경우에만 자동 하이라이트를 플러그인 방식으로 추가한다. HDR·AV1은 별도 호환성 트랙으로 분리한다.

## 의도적으로 후순위로 둘 항목

- 커뮤니티 피드, 계정, 클라우드 업로드: PulseClip의 로컬 우선·무계정 가치와 운영 비용에 충돌한다.
- 생성형 AI 편집: 기본 트림·오디오·내보내기 신뢰성이 확보되기 전에는 비용 대비 핵심 과업 개선이 작다.
- DLL 주입 기반 게임 후킹: 안티치트, 보안, 유지보수 위험이 높다.
- 라이브 스트리밍: 녹화·즉시 리플레이 제품 범위를 크게 확장하므로 별도 제품 결정이 필요하다.

- [DOR Minecraft 녹화 안내](https://clip.dor.gg/en/games/minecraft): 게임 자동 감지, 전체 녹화, 한 번의 클립 저장, 하드웨어 인코딩을 강조한다.

- [Electron 업데이트 안내](https://www.electronjs.org/docs/latest/tutorial/updates): Windows 업데이트 피드와 자동 업데이트 전달 구조를 설명한다.
- [Microsoft SmartScreen 평판 안내](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation): 일관된 서명 ID와 모든 릴리스 서명이 배포 신뢰 형성에 중요하다.
